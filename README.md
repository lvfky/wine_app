# Отбор хороших вин

Приложение показывает вероятность того что вино хорошее и решение модели при выбранном пороге. Модель это логистическая регрессия из ноутбука, внутри приложения она не обучается

## Как запустить

Версия Python: 3.12.8

Из папки wine_app:

```bash
pip install -r requirements.txt
streamlit run app.py
```

Приложение откроется в браузере на http://localhost:8501

## Что есть в папке

- `app.py` само приложение
- `model.joblib` обученный пайплайн, StandardScaler и LogisticRegression
- `config.json` порог по умолчанию
- `test.csv` тестовая выборка для вкладки с метриками
- `requirements.txt` версии библиотек

## Почему такое кэширование (задание 4.5)

Для модели используется `st.cache_resource`, потому что это один объект на весь сервер, он просто хранится в памяти и не копируется. Модель мы не меняем, только вызываем predict_proba, поэтому один общий объект для всех пользователей это нормально.

Для таблиц используется `st.cache_data`, потому что он сохраняет сами данные и каждому вызову отдает новую копию. Если где-то случайно поменять таблицу, у других пользователей и при следующем запуске скрипта она останется исходной

Вероятности на тесте тоже считаются один раз через `st.cache_data`. У аргумента `_model` есть подчеркивание, чтобы Streamlit не пытался его хешировать. Когда двигаем слайдер меняется только сравнение с порогом, predict_proba заново не вызывается

Если вызвать `joblib.load` без декоратора, то модель будет заново читаться с диска при каждом действии пользователя, потому что Streamlit выполняет весь скрипт сверху вниз. Работать будет, но приложение станет медленнее и все это будет зря, потому что модель от порога не зависит
